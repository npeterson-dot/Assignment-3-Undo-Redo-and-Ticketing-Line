I used two different data structures in this assignment because the order that information needs to be handled is different for each system. A stack is the right choice for undo and redo because it follows Last In, First Out. The most recent action a user performs should also be the first action they can undo. When an action is undone, it moves to the redo stack so it can be brought back if needed. This makes the order of the stack fit naturally with how undo and redo works in an actual program.
A queue works better for the help desk because it follows First In, First Out. The first customer who enters the line should be the first customer helped. New customers are added to the rear of the queue while customers are helped from the front. This keeps the support line fair and in the same order that customers arrived.
My implementations also differ from Python's built-in lists because I created the structures myself using nodes and pointers. Each node stores a value and a reference to the next node. The stack keeps track of the top node, while the queue keeps track of both the front and rear. Python lists already handle their internal structure for the programmer, but building these structures myself helped me understand how the order and connections between values are actually managed.
